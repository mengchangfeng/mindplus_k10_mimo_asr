# K10 MiMo语音识别与合成 Mind+扩展

面向行空板 K10 的 ArduinoC Mind+ 用户扩展，封装语音识别与非流式语音合成：

- 初始化 MiMo API Key 和音色
- 开始录音
- 结束录音并返回识别结果
- MiMo 合成语音（文本、风格）

底层使用 K10 板载 ES7243E/I2S 麦克风采集 16kHz/16bit 单声道 WAV，并调用 `mimo-v2.5-asr` 识别；语音合成固定使用 `mimo-v2.5-tts`，返回 24kHz/16bit 单声道 WAV 后通过 K10 扬声器播放。

## 使用

1. Mind+ 切换到上传模式，选择 K10/ESP32-S3 对应主控。
2. 扩展中本地导入本目录的 `config.json`。
3. 先用 Mind+ 自带 WiFi 积木连接网络。
4. 调用“初始化 MiMo”，填入 API Key 和音色（例如“冰糖”）。API 地址和模型已固定为 MiMo 官方接口。
5. 调用“开始录音”开始后台录音。
6. 调用“结束录音并返回识别结果”停止录音并获得识别文本。

录音最长时长固定为 5 秒。语音合成积木的风格参数可填写“温柔、缓慢”等自然语言，留空使用默认自然语气。

扩展不依赖 ArduinoJson；请求文本使用内置 JSON 转义，识别结果使用转义感知的轻量字符串提取，避免 Mind+ 环境缺少 `ArduinoJson.h` 导致编译失败。

## 库结构

ArduinoC 运行时已迁移到 `K10MimoAudio.h + K10MimoAudio.inl` 头文件库，积木生成器只负责导入库并调用初始化、录音、识别和语音合成接口。采用 `.inl` 而非单独编译 `.cpp`，避免 Mind+ 生成库依赖文件时出现路径错误。

`K10MimoAudio` 库内部需要导入 `unihiker_k10.h`，以使用 K10 底层提供的 `xI2SMutex` 管理麦克风和扬声器对 I2S0 的共享访问；库不会创建新的 K10 对象或 I2S 互斥锁。

## 0.0.9 验证

- PlatformIO 已通过 `K10MimoAudio`、`DeepseekLLM` 与 K10 官方库的组合编译，未出现重复定义或头文件顺序错误。
- K10 真机完成三轮连续 TTS → ASR：三次语音合成均成功，三次录音识别均返回结果，验证了重复录音任务、PSRAM 缓冲区和 I2S 资源释放。
- 压力验证首轮曾出现一次可恢复的 `HTTP -11`，随后调用及第二轮完整三次循环均成功；网络或接口超时仍会由积木返回现有 HTTP 错误。

## 变更

- `0.0.9`：将 ArduinoC 的 ASR、TTS、HTTP、WAV、Base64、I2S 和录音任务实现迁移到 `K10MimoAudio` 头文件库，积木生成器收敛为薄调用层。
- `0.0.8`：移除扩展层重复生成的 `unihiker_k10.h` 导入，改由 K10 主控程序统一提供。
- `0.0.7`：移除未直接使用的 `WiFi.h`，并统一 ArduinoC 头文件生成器 ID，避免与其他 K10 扩展组合时重复生成 `include`。
- `0.0.6`：移除 ArduinoJson 依赖，改用无第三方库的 MiMo 识别结果解析，提升培训电脑的 Mind+ 环境兼容性。
- `0.0.5`：增加 MiMo 非流式语音合成；固定 API 地址和模型，初始化只保留 API Key 与音色；增加每次请求后的音频、Base64、HTTP 和 I2S 资源清理。
